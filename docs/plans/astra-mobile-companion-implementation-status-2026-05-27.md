## Product guardrails implemented

- Mobile app is positioned as Review Companion, not Mobile Translator.
- Ordinary mobile UI avoids provider/model/API-key/token/quota/relay language.
- Existing desktop/web capture remains the source of saved learning assets.
- Mobile review supports offline-first local review choices and later sync.
- Weekly Digest preview/archive is learning-focused and limited to saved/reviewed/source summary content; server generation derives from synced learning records without provider/model/server-configuration language in mobile UI.
- Reminder controls are opt-in/device-local; the app does not request reminder permission on first launch.
- Reminder scheduling uses Expo Notifications and only asks permission from a user-initiated reminder action.
- Remote push token registration is opportunistic and happens only after a user-initiated reminder or weekly-note preference action; disabling weekly notes clears the stored current-device push token without interrupting the local preference change.
- Session tokens are stored through SecureStore, not regular AsyncStorage JSON.
- Persisted session endpoints are revalidated before authenticated mobile API calls in non-dev bundles, so stale local/dev `relayBaseURL` values cannot silently drive production traffic back to localhost or non-HTTPS services.
- Mobile release metadata no longer includes a dev API endpoint fallback in `app.json`; production endpoint configuration must be supplied explicitly through release environment, and verifier coverage blocks reintroducing local/non-HTTPS defaults.
- EAS preview/production profiles now carry public non-secret build-profile markers so release-like endpoint checks are auditable even when `EAS_BUILD_PROFILE` is not available inside the JavaScript runtime.
- Desktop link codes are short-lived, single-use relay records and do not expose server/provider configuration in mobile UI.
- Email sign-in code requests return generic responses, avoid account-existence disclosure, use bounded request/redeem throttling, ignore forwarded IP spoofing for these unauthenticated limiter keys, only include a code in API responses when the explicit development/test echo flag is enabled, mint redeemable production codes only after configured Resend delivery succeeds, and avoid sending codes/API keys to arbitrary Resend base URLs.
- Apple/Google OAuth identity redemption supports production provider ID-token verification when `ASTRA_OAUTH_GOOGLE_CLIENT_IDS` / `ASTRA_OAUTH_APPLE_CLIENT_IDS` are configured; provider tokens must match a request nonce, the development-only pre-verified payload path remains gated by `ASTRA_OAUTH_IDENTITY_DEVELOPMENT_REDEEM`, known production Astra hosts are refused by that development route, and caller-provided email claims do not bind development OAuth identities to existing accounts.
- Mobile Apple/Google launch wiring never fabricates identities: if a provider launch cannot produce an ID token with the generated nonce, the app shows a safe unavailable/failure message and avoids OAuth redemption.
- QR scanning is user-initiated and requests camera permission only when the user taps the scanner action.
- Destructive cloud learning-data deletion is user-confirmed, scoped to synced saved cards/review history, uses the account lifecycle grace-period job instead of deleting silently from the device, and leaves recent status references visible in Me.
- Full account deletion is also user-confirmed and clears the relay account plus local mobile state; external billing/support/video/audit retention side effects remain a production policy integration follow-up.
- Mobile retention analytics use count/action metadata only and intentionally exclude card text, snippets, email addresses, tokens, and full URLs; remote upload is disabled while unsigned/sample-only and is re-sanitized server-side before bounded per-user storage.
- Mobile retention ops summary is operator-only and aggregate-only: it returns event names, UTC buckets, counts, schema/source metadata, and explicit privacy flags while omitting email, owner/device/event/session IDs, raw metadata values, content, URLs, and per-user timelines.
- Weekly Digest delivery ops summary is operator-only and aggregate-only: it reports run/channel counts from metadata-only ops audit entries, exposes provider/relay API acceptance as `relayAcceptedCount`, and explicitly does not claim inbox delivery, APNs/FCM device delivery, provider webhook receipt coverage, user opens, or digest-content visibility.
- Mobile support help notes are explicit user actions, require a signed-in authenticated session, and submit metadata-only bundles to the existing support inbox with content inclusion disabled.
- Account data export is explicit, authenticated, intentionally redacts credential hashes and raw push tokens from the export payload, and returns `Cache-Control: no-store` / `Pragma: no-cache`.
- `Not useful` review feedback is device-local and metadata-only; it suppresses the card from Today without uploading the card text, saved sentence, source URL, or user content.
- Share Card is user-initiated and privacy-safe by default; native share text excludes raw source URLs, full page paths, token-like query strings, screenshots, and page content.
- Card speech is user-initiated, front-only, locally normalized/truncated, and does not speak source URLs, source titles, translations, explanations, or page content by default.
- Library saved-item Speak is user-initiated, row-level, and guarded as a separate release surface from Today review-card Play/Speak; test and verifier coverage keep the action hidden unless wired and preserve the front-only saved-expression contract.
- Review-card `View source` stays inside the mobile learning library and reuses existing Source Detail controls; opening the original URL remains a separate explicit action.
- Private source title controls are device-local and privacy-first: masked sources remain reviewable, mobile UI/share/source actions use the placeholder and omit origin/raw URL until the user shows the title again, and item-ID anchors prevent cloud source-title/URL refreshes from accidentally revealing a masked source.
- Mobile membership display avoids provider/model/quota/token/relay/API-key/backend terminology and avoids purchase/checkout/subscribe/upgrade CTAs; session `expiresAt` is treated as session expiry, not membership expiry.
- Learning-guidance copy is present in-app and in Store/TestFlight/Play drafts, frames Astra as a study aid, avoids guaranteed-accuracy claims, and preserves the mobile review-companion boundary.
- Accessibility V0 now has a testable helper baseline for touch targets and labels; final signed-build VoiceOver/TalkBack smoke testing remains a release checklist item.
- Mobile verifier coverage now protects store/release artifact regressions for learning-guidance, Accessibility V0 requirements, permission-purpose disclosure, account-deletion store/privacy coverage, Android unused-permission blocking for microphone/storage/overlay, stale analytics-local-only privacy claims, development email-code echo display, user-facing helper copy in `mobileMembership.ts`, listing/screenshot/release-checklist coverage for privacy-safe sharing / Play-Speak / Not useful / source-title hiding / account export / metadata-only help note, release-pack README coverage for the same alignment contract, required runtime/client tests for production API endpoint safety, native iOS privacy/linking artifacts, no-microphone native usage copy, EAS release-profile markers, committed-env secret hygiene, non-empty iOS privacy-manifest data categories, store-copy placeholder/tentative-privacy-answer cleanup, and reviewer-note template coverage.
